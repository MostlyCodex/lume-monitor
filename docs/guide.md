# 部署与管理

本指南适用于 **v1.1.0**，按 `npm run manage` 菜单说明操作。命令均在**管理电脑的 `worker/` 目录**运行。

数据库由管理工具自动初始化和检查，无需手动执行 SQL。

## 进入管理菜单

- 管理电脑：Git、Node.js 22.12+、SSH/SCP；Windows 可使用 PowerShell。
- VPS：使用 systemd 的 Linux，amd64 或 arm64 架构，具备 `diff`、`stat` 等基础命令，SSH 用户具有 sudo 权限。
- Cloudflare 账号；Telegram Bot 的用户名和 Token。首次使用时，在 `@BotFather` 发送 `/newbot` 创建 Bot，参见[官方说明](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)。

```bash
git clone https://github.com/MostlyCodex/lume-monitor.git
cd lume-monitor/worker
npm ci
npm run doctor
npm run manage
```

`doctor` 检查通过后进入菜单；管理工具自动获取对应版本的 Linux Agent 并校验 SHA-256，无需手动下载；有预编译 Agent 时无需 Go；预编译文件不可用时，管理电脑需 Go 1.26+ 从源码构建。SSH 端口、私钥和跳板机写入本机 `~/.ssh/config`，先用 `ssh my-vps` 确认能登录。`my-vps` 为示例别名，请替换。

```text
Lume 管理
  1. 从零部署
  2. 接管已有部署
  3. 查看状态
  4. 新增 VPS
  5. 配置节点
  6. 部署配置 / 更新 Agent
  7. 下线节点
  8. 恢复节点
  9. 永久删除节点 / 卸载 Agent
  0. 退出
```

首次部署选 **1**，接管线上应用选 **2**，日常管理先选 **3**。输入、操作结果、错误和取消提示以分隔线分组。

涉及 VPS 修改时，操作末尾显示“VPS 变更”：列出实际变更的 Lume 受管文件、当前行号及必要的原行号；删除项使用原行号，二进制、符号链接和备份目录不标行号。另列 Agent 服务状态变化，不展示文件内容或密钥。失败时仍汇总已发生的变更；清单未取回时会明确提示。仅保存本地配置不会生成 VPS 变更清单。

输入编号选择操作；回车采用方括号内的默认值。确认输入 `y / yes / 是` 或 `n / no / 否`，错误输入会提示重填。`/cancel` 或 Ctrl+C 取消当前操作；网络探针表单可用 `/back` 返回上一项，回车保留已填内容。

## 1. 从零部署

1. 填写 **Worker 名称**和 **D1 数据库名称**，可直接采用默认值。
2. “配置 Telegram Bot”选 `y`，填写 Bot **用户名**，可带 `@`；随后确认开始部署。
3. 按提示在浏览器中授权 Cloudflare。工具自动创建 D1、初始化或升级数据库并部署 Worker；若提示使用同名 D1，仅在它属于本部署时确认。
4. 按提示粘贴 Bot Token。等到“后端部署完成”，保存终端给出的 `/bind ...` 命令。
5. “现在添加并安装首台 VPS”选 `y`，按[第 4 项](#4-新增-vps)填写；选 `n` 可稍后从菜单新增。
6. 私聊自己的 Bot，发送完整的 `/bind ...`；绑定后发送 `/panel` 打开面板。

首台节点提示“Agent 实际配置与本次部署一致”，且面板能看到节点，即完成上线。中断后重选 **1**；已有 `wrangler.jsonc` 但缺少本地管理记录时，会自动转入接管。

## 2. 接管已有部署

1. 将现有部署的 `wrangler.jsonc` 放入 `worker/`，准备 `ADMIN_TOKEN` 及各节点的 Agent 配置。管理令牌可从原管理电脑的 `.lume/state.json` 的 `adminToken` 字段查找。
2. 选择 **2**，输入节点配置实际使用的 **Worker HTTPS 根地址**及 `ADMIN_TOKEN`。地址不带 `/dashboard/` 等路径。已有本地记录时，先确认重新核对，旧记录会自动备份。
3. 按提示完成 Cloudflare 授权及 D1 结构检查；若提示缺少管理接口，确认更新现有 Worker 后继续。
4. 为清单中的每个节点选择配置来源：

| 选项 | 操作 |
| --- | --- |
| `1 SSH 读取` | 输入该 VPS 的 SSH 目标，工具读取 `/etc/vpsmon/config.json`；需要 root 或免密码 sudo |
| `2 本地配置文件` | 输入对应节点的完整 JSON 配置文件路径，再填写后续管理使用的 SSH 目标 |

所有现有密钥均须核对，包括尚未上报的节点。看到“已核对全部现有密钥并建立本地管理状态”后，选 **3** 检查。

## 3. 查看状态

选择 **3**，查看 Worker 地址、部署阶段、节点安装记录和最近上报。

| 显示内容 | 下一步 |
| --- | --- |
| `未找到本地部署管理状态` | 首次部署选 **1**，已有部署选 **2**；此提示不代表线上未运行 |
| `配置待部署` | 选 **6** 下发已保存的配置 |
| `配置已生效` | Agent 已加载与本地一致的配置 |
| `上次应用失败，待重试` | 检查部署错误，选 **6** 重试 |
| `配置已写入，待启动确认` | Agent 处于停用状态；需要恢复节点时选 **8** |
| `Worker 尚不支持配置核验` | 选 **6**，工具先更新 Worker，再部署 Agent |
| `Agent 未上报配置摘要` / `本地与 Agent 配置不一致` | 选 **6** 更新 Agent 并核验 |
| `配置无法核验（后端不可达）` | 检查网络及 Worker 状态 |
| `恢复待完成` | 选 **8** 继续恢复 |
| `已下线` | 需要重新上线时选 **8** |
| `永久删除待完成` | 修复所提示的问题后选 **9** 继续 |
| `已启用但未纳入本地管理的节点` | 选 **2** 核对线上部署，补全管理记录 |
| `已禁用的远端目录记录` | 目录中已禁用的节点；需要彻底清除时使用菜单 9 |
| `尚未上报` | 未安装的节点选 **6**；已安装的节点查看健康检查结果及 Agent 日志 |

`✓` 表示本地记录为已安装，运行情况以最近上报和面板为准。GitHub 发布不会自动更新私有部署；Worker 与 Agent 分别部署后，新功能才生效。

## 4. 新增 VPS

### 填写节点信息

选择 **4**，按顺序填写：

| 输入项 | 填写方式 |
| --- | --- |
| 节点 ID | 唯一标识，如 `hk-01`；1–32 位小写字母、数字、`_` 或 `-`，首位为字母或数字；不得与现有或已下线节点重名 |
| 面板显示名、用途、国家 / 城市 | 自定义展示文字，如 `香港 01`、`中转`、`香港`；每项最多 80 字节 |
| systemd 服务 | 填 VPS 上实际存在的服务名，如 `nginx.service,sshd.service`；英文逗号分隔，最多 16 个，每项 1–80 位字母、数字或 `_.@-`；不监测服务时留空 |

节点 ID 与 SSH 别名可以不同。服务名称可在 VPS 用 `systemctl list-units --type=service --all` 查看；这里只读取服务状态。

### 选择网络质量监测

| 选项 | 后续操作 |
| --- | --- |
| `1 三网 ICMP` | 填目标地区（可留空），再依次填电信、联通、移动的参考目标 IP 或主机名；一次生成 3 个探针 |
| `2 复用已有节点的外部探针` | 选来源节点，再选探针编号；多个编号用英文逗号分隔，回车全选，`0` 返回 |
| `3 自定义 ICMP / TCP` | 选 `icmp` 或 `tcp`，填目标；TCP 另填 `1–65535` 的端口，再填显示名。出现关联节点列表时，外部目标选 `0`，节点间链路选对应编号；添加完毕后，继续添加选 `n` |
| `0 结束，本次不添加` | 跳过添加网络探针 |

目标支持 IPv4、IPv6 或主机名，不带协议、端口或路径。三网目标需自行确认运营商归属，或复用已有配置。每节点最多 **32 个网络探针**，三网占 3 个；不配置探针时仍监测主机资源和所选服务。

节点间链路配置在**发起探测的节点**上，双向观测需两端分别配置。ICMP 显示延迟与丢包，TCP 显示建连延迟与失败率；三网历史从启用后开始积累。指标定义见[测量口径](reference/monitoring-methodology.md)。

### 设置网卡与周期流量

填写 **SSH 部署目标**：别名、主机名或 IP，可带 `user@`，端口和私钥在 SSH 配置中指定。留空只登记节点，稍后选 **6** 补填目标并安装。

随后配置流量统计：

- **网卡**：通常选 `1 自动`，采用单一默认路由网卡。需要指定范围时选 `2`，从 SSH 读取的实际网卡列表中输入编号；多个编号用英文逗号分隔。不要同时统计桥接／隧道接口及其底层接口，以免重复计数。无法读取网卡时先采用自动模式，设置可用 SSH 后再选 **5** 调整。
- **周期流量**：默认 `n`。启用选 `y`，填写重置日 **1–31**，再选 **UTC** 或**北京时间**；在该时区的指定日 00:00 重置，当月没有该日则使用月末。

首次启用或更改统计设置时，从当前计数起算。Agent 重启保留累计值；系统或网卡重置会标记“监测覆盖不完整”。设置和计数连续、跨周期采样间隔不超过两个上报间隔时，新周期自动清除该标记。跨越重置点的流量无法精确拆分，因此周期值为估算，不代表服务商账单。

### 确认部署

核对监测摘要，在“按以上配置新增节点并继续部署”选 `y`。工具生成独立密钥、安装 Agent，并等待认证上报；需要 sudo 时在 SSH 提示中输入密码。看到“Agent 实际配置与本次部署一致”后刷新面板。

## 5. 配置节点

用于修改 systemd 服务、网络探针、统计网卡和周期流量。

1. 选择 **5**，从列表选节点编号或输入节点 ID，查看当前配置摘要。
2. 修改服务列表选 `y`，输入完整的新列表；留空会清空服务监测。选 `n` 保留原列表。
3. 选择网络探针操作：

| 选项 | 效果 |
| --- | --- |
| `1 保留` | 沿用现有探针 |
| `2 追加` | 保留原探针，进入[网络质量向导](#选择网络质量监测)添加新项 |
| `3 重新配置` | 用本次完成的新探针替换原列表；取消或选择“本次不添加”会保留原列表 |
| `4 删除指定项` | 按编号删除，英文逗号分隔；`0` 全部删除，回车全部保留 |

4. 如需调整网卡或周期，在“修改流量统计网卡与周期”选 `y`，按[网卡与周期设置](#设置网卡与周期流量)填写；选 `n` 保留。
5. 核对摘要，在“保存以上监测配置”和“现在部署到 VPS”依次选 `y`。

**保存只更新本地配置，部署后监测才生效。** 稍后部署或部署中断时，从 **6** 继续。

给已有节点补三网时，选“追加”，再选“三网 ICMP”或“复用”，最后保存并部署。单个未完成的自定义探针可取消，之前已填好的探针会保留。

## 6. 部署配置 / 更新 Agent

下发本地配置、安装已登记的节点或更新 Agent，均使用此项。

1. 升级 Agent 前，先退出菜单，运行 `git pull --ff-only`、`npm ci`，再运行 `npm run manage`。仅下发配置时跳过此步。
2. 选择 **6**，选目标节点；没有保存 SSH 目标时按提示补填。选择完成后即开始部署；若后端不支持当前 Agent 配置，工具先升级 D1 结构并更新 Worker。需要 Cloudflare 授权或 sudo 密码时按提示完成。
3. 等待“Agent 实际配置与本次部署一致”，再选 **3** 确认“配置已生效”，刷新面板查看结果。

更新前会备份并检查配置，升级脚本执行失败时回滚。原先停用的 Agent 更新后仍保持停用，并显示“待启动确认”；恢复已下线节点使用 **8**。

默认每 60 秒采集并上报。高级调整可编辑仓库根目录的 `.lume/nodes/节点ID/config.json` 中的 `report_interval_seconds`、`probe_interval_seconds`，再选 **6** 下发。节点或探针增多、间隔缩短时，应检查 Cloudflare D1 的实际用量。

## 7. 下线节点

1. 选择 **7**，选目标节点。
2. 核对摘要中的 SSH 目标和受影响的对端节点，在“确认下线”输入 `y`。
3. 按 SSH 提示完成授权，等待停用 Agent、撤销密钥、标记退役及对端配置更新全部完成，再选 **3** 确认节点出现在“已下线”列表。

VPS 和业务服务继续运行，Agent 保留供恢复使用，历史数据按保留策略处理。若摘要提示“跳过远端停机”，工具不会连接 VPS，需要自行确认 Agent 已停止。

## 8. 恢复节点

1. 选择 **8**，从已下线列表选节点，确认恢复及相关对端探针。
2. 工具优先使用保存的配置和 SSH 目标；若配置缺失，按提示选择 SSH 读取、本地配置文件或重新配置。
3. 等待密钥轮换、Agent 启动和相关对端配置部署完成。看到“已恢复”，再选 **3** 检查新上报。

仅可恢复通过 **7** 下线的节点。恢复中断后重选 **8** 继续。

## 9. 永久删除节点 / 卸载 Agent

1. 选择 **9**，选要删除的节点；已下线节点和删除未完成的节点也在列表中。
2. 选择通过 SSH 卸载并核对目标；仅在 VPS 已销毁或从未安装 Agent 时，选择对应选项。
3. 核对删除范围和关联节点，输入完整节点 ID 确认；输入 `/cancel` 取消。
4. 按提示完成 SSH / sudo 授权，等待“已永久删除”。结束时会列出 VPS 变更的文件路径及行号。

| 层面 | 清理内容 |
| --- | --- |
| VPS | Agent、systemd 单元、配置、报告队列、流量状态、升级备份及专用账号 |
| Worker / D1 | 节点密钥、禁用清单条目、目录、监测历史、告警及关联探针记录 |
| 管理电脑 | 节点配置、恢复记录、受管备份及其他配置中的关联探针；自动部署受影响的在线节点 |
| 浏览器 | 下次成功刷新时清除该节点的显示设置和历史缓存 |

**7 用于可恢复下线，9 用于永久删除，不能从 8 恢复。** 共享 Worker、D1 数据库及其他节点、VPS 业务服务继续保留。操作失败会保存进度，重选 **9** 继续；修复 SSH 或 sudo 问题后再重试。

清理范围为 Lume 受管数据；自行复制的备份、系统日志和云平台备份需在对应位置处理。

## 0. 退出

选择 **0** 关闭工具；线上监控继续运行，已保存的配置及待部署状态保留。

## 面板、备份与故障处理

- **访问面板**：私聊已绑定的 Bot 发送 `/panel`；`/status` 查询当前状态。访客可查看使用虚构数据的[公开演示](https://mostlycodex.github.io/lume-monitor/)。
- **节点信息**：点击节点卡片查看 vCPU 数、内存总量、根分区 `/` 容量、统计网卡和流量周期。节点正常上报但 CPU 显示“—”时，通过菜单 **6** 更新 Agent。
- **服务状态**：详情显示 Agent 上报的 systemd 服务状态。“服务监测 · 暂无上报”表示未收到服务结果；通过菜单 **5** 配置服务列表，再选 **6** 下发到 VPS。
- **显示设置**：右上角齿轮可修改显示信息、顺序及背景，预览后保存；取消或关闭会放弃修改。背景支持 JPG、PNG、WebP，最大 10 MB、2400 万像素，自动压缩和裁切，也可恢复默认。设置仅保存在当前浏览器，图片不上传，无需部署。
- **更新面板**：退出菜单后，在 `worker/` 执行 `git pull --ff-only`、`npm ci`、`npm run deploy`，自动检查数据库、构建并部署 Worker，然后核验线上版本；空数据库会自动初始化，已就绪的数据库保留数据；Agent 更新使用菜单 **6**。
- **刷新**：页面隐藏时暂停定时请求，重新可见时更新状态和已过期的历史数据；Agent 采集始终继续。
- **回滚面板**：在 `worker/` 执行 `npx wrangler versions list` 查看版本 ID，再运行 `npm run worker:rollback -- <版本ID>`。目标须使用同一 D1 和相同数据库结构标识；命令检查数据库与版本，回滚后等待在线节点的新上报并检查面板。失败时尝试恢复原 Worker；结构标识不同或 Secrets 已变化时停止。详见[开发参考](reference/development.md#更新与回滚-worker)。
- **周期累计备份**：VPS 上的 `/var/lib/vpsmon/traffic.json` 保存已观测流量，迁移 VPS 时一并保留。
- **备份**：完整备份仓库根目录的 `.lume/` 和 `worker/wrangler.jsonc`。其中包含令牌和节点密钥，应加密保管；更换管理电脑时恢复这两处文件，并配置 SSH 登录。

| 情况 | 处理 |
| --- | --- |
| 网卡无法识别或流量显示“—” | 选 **5** 指定实际网卡，再选 **6**；周期统计异常时查看 Agent 日志 |
| 已安装但没有新上报 | 在 VPS 运行 `sudo journalctl -u vpsmon-agent.service -n 30 --no-pager` 查看错误，修复后选 **6** 重试 |
| 提示线上密钥清单变化 | 选 **2** 重新核对完整部署，再继续管理 |
| 接管提示无法读取节点目录 | 更新代码和依赖后重选 **2**，让向导检查数据库结构；仍失败时根据 HTTP 状态检查令牌和 Worker 日志 |
| 下线后对端更新失败，原节点已不在可选列表 | 运行 `npm run node:remove -- hk-01` 续做，将 `hk-01` 替换为已下线的节点 ID |

批量节点和其他脚本调用方式可运行 `node ../tools/lumectl.mjs help` 查看。
